# astrbot_plugin_ark_guess

AstrBot 的《明日方舟》猜干员 / 猜敌人插件。基于 PRTS 数据（434 名干员、1718 名敌人），每个群同一时间只启用一个题库，每个题库各自一个对局，支持多局并行与实例级并发控制。

## 指令

| 指令 | 说明 |
| --- | --- |
| `/更换干员池` / `/更换敌人池` | 切换本群题库（必须带 `/`）；有进行中的对局时需先发送 `不猜了` |
| `@机器人 猜干员 <干员名>` | 干员池开局并立即猜测该干员 |
| `@机器人 猜敌人 <敌人名>` | 敌人池开局并立即猜测该敌人 |
| `玛一把` | 干员池可用；可裸发或@机器人触发，以玛恩纳作为第一次猜测开局 |
| `粥一把 <干员名>` | 干员池可用；可裸发或@机器人触发，开局并立即猜测该干员 |
| `@机器人 <名称>` | 对局开始后提交一次猜测（按当前题库解析） |
| `不猜了` / `@机器人 不猜了` | 结束并删除当前题库的对局；无对局时静默 |
| `/查干员 <关键词>` | 独立检索干员名称或 ID；支持名称片段和错字候选，只返回名称，不影响对局 |
| `/查敌人 <关键词>` | 独立检索敌人名称或 ID，规则同上 |
| `/角色池设置 <数字串>` | 设置本群答案稀有度（仅干员池生效），例如 `/角色池设置 1256` |
| `/猜测次数 <次数>` | 设置本群最大猜测次数（两个题库共用），例如 `/猜测次数 8`；`-1` 不限次数 |
| `/本群难度` | 查看本群当前题库与难度设置 |
| `/重置难度` | 恢复本群默认难度（题库也会回到干员池） |
| `/对局状态` | 查看当前题库的对局（最近 5 次猜测） |
| `/对局统计` | 查看本进程内两个题库的对局数量 |
| `/方舟帮助` | 指令说明 |

### 行为细节

- 题库切换：`/更换干员池` 与 `/更换敌人池` 必须带 `/`；切换后只能使用对应题库的开局指令——干员池用 `猜干员`，敌人池用 `猜敌人`，另一个指令会提示切换。
- 切换前如果有进行中的对局，会提示先发送 `不猜了` 结束，避免丢失进度；两个题库的对局互不影响。
- `@机器人 猜干员 <干员名>`：必须艾特机器人并提供干员名；作为首次猜测开局。缺少名字时只提示用法，不创建对局。
- `@机器人 猜敌人 <敌人名>`：敌人池开局指令，规则同上；缺少名字时提示 `@机器人 猜敌人 <敌人名>`。
- `玛一把`：干员池专属，可裸发或@机器人后发送；无对局时创建并立即提交玛恩纳作为第一次猜测，有对局时只显示当前进度。
- `粥一把 <干员名>`：干员池专属，可裸发或@机器人后发送；无对局时创建并立即提交该干员作为第一次猜测；已有对局时只显示当前进度，不新增猜测。缺少名字时不创建对局。
- `@机器人 <名称>`：仅对局进行中时作为猜测；同名重复猜测会被拒绝。
- `不猜了`：裸发或@机器人后发送均可；结束并删除当前题库的对局，无对局时不回复。
- `/查干员`、`/查敌人`：只查询题库，最多返回 10 个名称；没有直接匹配时尝试推荐错字候选。检索不会创建或修改对局，也不消耗猜测次数。
- `/角色池设置 <数字串>`：必须带 `/`，只影响本群干员池答案，例如 `/角色池设置 123456`、`/角色池设置 1256`、`/角色池设置 136`；数字可任意组合，只允许 1-6。
- `/猜测次数 <次数>`：必须带 `/`，只影响本群下一局的次数上限，例如 `/猜测次数 8`、`/猜测次数 10`；`/猜测次数 -1` 表示不限次数；`0` 与其他负数会被拒绝。
- 两项设置保存在 `plugin_data/astrbot_plugin_ark_guess/group_settings.json`，不同群互不影响；题库选择也会持久化。
- `/本群难度`：查看本群当前题库、稀有度、次数及来源（默认/自定义）。
- `/重置难度`：删除本群自定义设置，恢复全局默认（题库回到干员池）。

## 判定规则

### 干员（五维）

- 稀有度、实装年份：`🟩` 正确；`⬜⬆️` 答案更高 / 更晚；`⬜⬇️` 答案更低 / 更早
- 实装年份下方附带副标题（如 `日暮寻路`），由上线时间与 PRTS 活动一览推断，纯卡池实装则留空
- 职业（分支）：`🟩` 职业与分支均一致；`🟨` 同职业不同分支；`⬜` 职业不同
- 阵营：所属势力有交集 → `🟩`；仅隐藏势力交叉命中 → `🟨`；否则 `⬜`
- 种族：相等 → `🟩`，否则 `⬜`

阵营数据来自 PRTS `chara_data.ingameFaction`（所属势力）与 `hiddenFaction`（隐藏势力），多个势力以逗号分隔。

### 敌人（六维）

- 危险等级：`普通` < `精英` < `领袖`，方向提示同样使用 `⬆️` / `⬇️`
- 耐久 / 攻击 / 防御 / 法术抗性：PRTS 的 `E < D < C < B < B+ < A < A+ < S < S+ < SS` 评级
- 实装：来自敌人页面的 `登场活动`，只展示活动名；同活动 → `🟩`，否则按活动先后给出 `⬆️`（答案更晚）/ `⬇️`（答案更早）

> 敌人页与干员同名时（如 `W`、`凯尔希`、`弑君者`），抓取脚本会优先读取 `名称(敌方)` 页面的 `登场活动`。

## 结果图片

对局结果使用 Pillow 在本地绘制为 PNG：深色卡牌背景、维度色块、箭头与隐藏势力副标题，保存到 AstrBot `data/plugin_data/astrbot_plugin_ark_guess/cards/` 后以 base64 图片消息发送（协议端无需访问 AstrBot 本地文件）。

卡片列数由题库决定：干员 5 列、敌人 6 列（危险等级 / 耐久 / 攻击 / 防御 / 法术抗性 / 实装），标题分别为「猜干员」「猜敌人」。

干员的「实装」格以两行展示：大字为实装年份，小字为登场活动名。

分支格使用两行：大字为具体分支，小字标注所属职业（如 `职业：辅助`），便于判断“同职业不同分支”的黄色部分命中。

每个格子同时用颜色和符号区分：

| 状态 | 样式 | 含义 |
| --- | --- | --- |
| √ | 绿底绿框 | 完全正确 |
| ~ | 黄底黄框 | 部分命中（同职业不同分支，或隐藏势力交叉命中） |
| ↑ / ↓ | 蓝底蓝框 | 数值方向提示（答案更高/更晚，或更低/更早） |
| × | 红底红框 | 错误 |

- 不依赖 HTML 渲染服务或网络；
- 超过 1 小时的图片会在清理任务中删除；
- 中文字体优先使用微软雅黑 / Noto Sans CJK，Linux 部署需安装其中一种中文字体；
- 绘图失败时自动回退为文本表格并记录异常日志，设置 `render_mode=text` 可强制使用文本；未配置或配置为空时默认走图片。
- 启动日志会打印插件版本与解析后的 `render_mode`，每次出图会打印卡片路径与大小，便于确认运行的是哪份代码。

## 配置

`_conf_schema.json` 支持：

| 配置项 | 默认值 | 说明 |
| --- | --- | --- |
| `max_attempts` | 8 | 每局最大猜测次数 |
| `game_ttl_minutes` | 120 | 空闲对局回收时间（分钟），`<=0` 不回收 |
| `cleanup_interval_seconds` | 600 | 过期检查间隔（秒） |
| `min_rarity` | 1 | 出题池最低稀有度 |
| `render_mode` | image | `image` 本地 Pillow 生成 PNG 卡片；失败自动回退 `text` 文本表格 |

## 并发与实例隔离

- 每个群（`event.get_group_id()`）固定绑定一个对局；私聊按会话区分；
- 同一群再次触发开局指令不会新建对局，而是返回当前进度；
- 每局拥有 `game_<random>` 唯一 id，答案、猜测历史、状态只保存在该实例内；
- 同一对局的提交由 `asyncio.Lock` 串行化，并发猜测不会丢失或覆盖；
- 不同群使用独立对局与独立锁，可并行推进；
- 对局默认保存在进程内存中，插件重载 / AstrBot 重启会丢失；空闲对局按 TTL 自动回收。

## 数据更新

干员题库由外部的 Node 数据管线生成（与本插件仓库分离）：

```powershell
# 在数据管线仓库中执行
npm run fetch

# 将生成的 operators.json 复制到插件 data/ 目录
Copy-Item .\data\operators.json <插件目录>\data\operators.json -Force
```

敌人题库由仓库内脚本直接抓取：

```powershell
cd <插件目录>
python scripts/fetch_enemies.py
```

脚本会读取 PRTS `敌人一览/数据`（危险等级与四维评级），再批量抓取敌人页面的 `登场活动`，输出 `data/enemies.json`（含 `debut` 与 `debut_order`）。

然后在 AstrBot WebUI 的插件页重载插件。`operators.json` / `enemies.json` 中都包含 `version`，插件启动日志会打印当前题库版本与条目数量。
